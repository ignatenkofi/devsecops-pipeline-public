## [Unreleased]

### Fixed
- **Ночное самообновление не работало ни одной ночи** с момента мержа
  (прогоны 29, 30, 31 июля — все красные, все на одном и том же шаге).
  Негатив-фикстура gitleaks использовала каноническую пару `AKIA…EXAMPLE`
  из документации AWS, а современный gitleaks её намеренно не репортит
  (allowlist на example-значения): 8.18.4 находил, 8.30.1 — уже нет.
  Гард не мог пройти в принципе, ветка `bump/tools` и PR ни разу не
  создавались. Фикстуры заменены на синтетические (AWS access key, GitHub
  PAT, Slack bot token) — проверены обоими бинарями, 8.18.4 и 8.30.1.
- Фикстура и проверка вынесены в `tests/negative/` и используются обоими
  воркфлоу. Копипаста и была причиной, по которой протухание заметил только
  ночной прогон, а selftest на действующем пине оставался зелёным.
- Проверка требует **все** эталонные находки, а не «хотя бы одну»: отвалившееся
  правило обязано назвать себя и уронить прогон, а не тихо деградировать до
  одной работающей проверки.

### Added
- **Признак живости для ночного прогона** (`.github/scripts/health-issue.sh`):
  провалившийся scheduled-workflow сам о себе не сообщает — краснеет во
  вкладке, куда никто не заходит. Теперь падение заводит issue, а зелёная
  ночь её закрывает. Одна тема отказа = одна issue, ночь за ночью
  обновляется комментарием.
- **Мажорные бампы больше не блокируют минорные.** Job применяет только
  не-мажорные обновления; мажор остаётся на текущем пине и уезжает в
  отдельную issue со ссылкой на разбор changelog. Раньше минор и мажор
  ехали одним PR, и «минорные мержатся пачкой» не работало.
- **Прогон самих composite actions на версии-кандидате** до правки пинов:
  негатив-фикстуры проверяют «инструмент всё ещё находит», этот шаг —
  «стадия всё ещё запускается» (имена команд, флаги, коды возврата). Ровно
  этот класс поломок приносят мажоры вроде osv-scanner 1.x → 2.x.
- Валидация гоняется каждую ночь, даже когда бампать нечего: ночь без бампа
  теперь доказывает, что гарды на действующем пине по-прежнему держат.
- **Nightly-самообновление пинов** (`nightly-bump.yml`, приватный #8):
  ночной workflow сверяет пины gitleaks/semgrep/osv-scanner с апстримом
  (GitHub Releases / PyPI), валидирует новые версии на негатив-фикстурах
  selftest ДО правки пинов и открывает/обновляет PR `bump/tools` с таблицей
  «было → стало». Политика: минорные — пачкой, мажорные — с разбором
  changelog (README «Версионирование»).
- **M1-правила offline-набора semgrep** (приватный #8): intra-file path
  traversal (`py-open-request-path`, `js-fs-request-path`) и SSRF
  (`py-requests-request-url`, `js-fetch-request-url`) — только прямой поток
  «request-параметр → sink» одним выражением, без претензии на taint-анализ
  («Границы честности»). Selftest дополнен негатив-фикстурами на все четыре
  правила и позитивом на безопасных аналогах (allowlist-маппинг, статический
  URL) — ложных срабатываний нет.
- Класс `vuln-demo` — намеренно уязвимое демо (sqst-vulnerable-app): все
  лёгкие стадии advisory (в т.ч. secrets), витрина находок без блокировок.
  Санкционированное исключение из инварианта «secrets = B» в selftest.

## [1.0.0] — 2026-07-22

### Added
- Публичный компаньон приватного `devsecops-pipeline`: лёгкие стадии как
  переиспользуемый workflow для публичных репозиториев (обход ограничения
  GitHub public→private reusable workflow).
- `pipeline-light.yml` (workflow_call, `repo-class` + `skip-stages` /
  `extra-stages`) — точка входа.
- Composite actions: `profile-resolve`, `gitleaks`, `semgrep` (+offline-rules),
  `osv-scanner`, `sarif-report` (перенесены из приватной части, тот же набор).
- Профили `library` / `service` / `docs-shelf` / `course-content`.
- `selftest.yml`: валидация профилей + позитив/негатив-прогоны стадий.
- Учебный слой: `docs/LESSON.md` (разбор shift-left и границы taint-анализа),
  `examples/security.yml`, образовательный README. MIT-лицензия.
